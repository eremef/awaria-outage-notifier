ci: Optimize Docker multi-arch builds and fix Windows release script

Maintainer Notes:
- Performance: Dropped QEMU emulation in favor of GitHub's native ARM runners (`ubuntu-24.04-arm`) for the Add-on Docker image build. This reduces build times from 2.5 hours down to the native build speed (~15 mins).
- CI/CD: Implemented Docker's `push-by-digest` strategy. The workflow now splits into a matrix of architectures (amd64 and arm64), pushes raw blob digests, and then a dependent `merge` job stitches them into the final multi-arch manifest using `docker buildx imagetools create`.
- Bug Fix: Fixed `release.rs` execution on Windows which crashed on `Command::new("npm")` because Windows strictly requires the `.cmd` extension for batch files.

Summary of Changes:
- `.github/workflows/addon-release.yml`: Refactored to matrix strategy with `ubuntu-latest` and `ubuntu-24.04-arm`. Replaced QEMU action with `imagetools create` merging step.
- `release.rs`: Changed npm invocation to resolve `npm.cmd` dynamically on Windows.

User-facing:
- Home Assistant Add-on automated releases are now lightning fast.
- The local `./release <version>` script now succeeds completely on Windows without throwing `program not found` errors.
